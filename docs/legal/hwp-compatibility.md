# HWP·HWPX 호환성 및 법적 입장

DocuAX의 한컴 한글 파일 처리에 대한 면책 조항 및 법적 근거.

## 핵심 입장

- **상표**: "한글", "한컴", "HWP", "HWPX"는 (주)한글과컴퓨터의 등록 상표입니다. 본 프로젝트는 한글과컴퓨터와 **제휴·후원·승인 관계가 없는 독립적인 오픈소스 프로젝트**입니다.
- **호환성**: DocuAX는 한국 회사·공공기관 사용자가 본인 소유 HWP/HWPX 파일을 마크다운으로 변환·편집·재출력하기 위한 **합법적 호환성 도구**입니다.
- **역공학**: 한컴이 공개한 HWP 5.0 스펙 문서와 오픈소스 라이브러리(`python-hwpx`, `pyhwp` 등)를 기반으로 합니다. DocuAX 자체는 역공학을 수행하지 않으며, 의존 라이브러리들의 처리에 의존합니다.

## HWP 처리 의존성

| 포맷 | 사용 라이브러리 | 라이선스 |
|---|---|---|
| HWP 5.x (.hwp, OLE) | `pyhwp` 0.1b15 (CLI `hwp5txt`) | GNU AGPL v3 |
| HWP 5.x (.hwp, 폴백) | `olefile` 0.47 (PrvText 스트림) | BSD |
| HWPX (.hwpx, OWPML) | `python-hwpx` 2.9.1 | MIT |
| 추출 후 표현 | 마크다운 (CommonMark + 표 확장) | — |

위 라이브러리는 모두 정식 오픈소스이며, 각 프로젝트의 라이선스 조건을 준수합니다.

## 법적 근거 — 호환성을 위한 역공학 허용

### 한국 — 저작권법 제101조의4 (프로그램코드역분석)

> 정당한 권한에 의하여 프로그램을 이용하는 자 또는 그의 허락을 받은 자는, **호환에 필요한 정보를 쉽게 얻을 수 없고 그 획득이 불가피한 경우** 프로그램의 호환에 필요한 부분에 한정하여 프로그램의 저작재산권자의 허락 없이 프로그램코드역분석을 할 수 있다.

조건:
1. 독립적으로 창작한 컴퓨터프로그램과의 **호환에 필요한 정보를 얻기 위해**
2. 그 프로그램의 기능을 **조사·분석·시험하는 행위**

DocuAX의 HWP/HWPX 처리는 위 조건에 부합합니다.

### 미국 — DMCA §1201(f)

상호운용성(interoperability)을 위한 역공학을 명시적으로 허용합니다.

### 유럽 — Computer Programs Directive (2009/24/EC) §6

상호운용성을 위한 역컴파일(decompilation)을 허용합니다.

## 호환 소프트웨어의 정당성 — 판례·선례

호환 제품 개발은 전 세계적으로 정당한 경쟁으로 인정됩니다:

| 호환 제품 | 대상 | 비고 |
|---|---|---|
| LibreOffice | Microsoft Office (.docx) | 역공학 + OOXML 공개 스펙 |
| Chrome | Internet Explorer (HTML) | 표준 + 호환 구현 |
| Wine | Windows API | API 재구현 |
| Samba | Windows SMB 프로토콜 | 프로토콜 호환 |
| 반디집·빵집 | ALZ·EGG 포맷 | 상용 호환 제품 |
| 폴라리스오피스 | HWP | **상용 HWP 호환 제품** (선례) |
| 하나워드 | HWP | 상용 HWP 호환 제품 |

DocuAX는 위 선례와 동일한 정당한 호환성 도구입니다.

## HWP 5.0 스펙 정오표 참고

한컴이 공개한 HWP 5.0 스펙 문서와 실제 바이너리 구현 간 불일치가 다수 보고되어 있습니다. 대표 예 (rhwp 프로젝트의 공개 정오표 발췌):

| # | 불일치 내용 |
|---:|---|
| 1 | BorderFill 직렬화 순서가 스펙과 다름 (순차 → 인터리브) |
| 3 | GShapeObject 바이트 오프셋 4바이트 차이 |
| 10 | ParagraphShape의 첫 2비트가 정렬이 아닌 미사용 필드 |
| 27 | PrvImage가 BMP/GIF가 아닌 PNG 포맷 사용 |

전체 27건 — 외부 공개 자료에서 확인 가능. 공개 스펙대로 구현하면 파일이 깨지므로, 호환 라이브러리들은 실제 바이너리 동작을 기준으로 정정합니다. 이는 **공개된 사실의 발견**이지 역공학이 아닙니다.

DocuAX는 자체적으로 정오표 처리를 하지 않으며, 의존 라이브러리(`pyhwp`, `python-hwpx`)에 처리를 위임합니다.

## 사용자에게의 약속

1. **사용자 본인 소유 파일만 처리** — 무단 배포된 한컴 파일에 본 도구 사용은 사용자 책임
2. **상표 정상 표기** — 본 문서·README·UI 모두에 한컴 상표 면책 명시
3. **한컴 폰트 미사용** — 오픈 라이선스 폰트(Pretendard, Noto Sans/Serif KR, 나눔고딕, 맑은 고딕 OS 동봉본)만 사용
4. **변환 정밀도 한계 공지** — HWP → 마크다운 변환은 손실 변환임. 사용자에게 명시적 안내

## 변환 한계 (정직한 공지)

| 입력 → 출력 | 보존 | 손실 |
|---|---|---|
| HWPX → 마크다운 | 본문·헤딩·표·글머리 | 정밀 페이지 여백·결재선·도장·일부 서식 |
| HWP (5.x) → 마크다운 | 본문 텍스트·표 (pyhwp 기반) | HWPX보다 많은 서식 손실 — HWPX 권장 |
| 마크다운 → HWPX | 기본 구조 100%·제목·헤딩·표·글머리·검토 태그 | 페이지 머리말·결재선 (수동 보완 필요) |
| 마크다운 → DOCX/PDF | 모든 구조 + 색상·테마 | — |

**권장**: 헤비유저는 변환 후 한컴 한글에서 결재선·인장 추가. 워커는 DOCX/PDF 출력으로 시각 미감 극대화.
