# Docuax v3 — 워드프로세서 UI 개편 설계서

- 날짜: 2026-07-05
- 상태: 승인됨 (사용자 승인, 대화 중 확정)
- 작업 위치: `C:\project\docua` (기존 `Documents\docuax`에서 복사, git 히스토리 유지)

## 1. 목표

기존 Docuax(마크다운 → 한국 회사 문서 변환 SaaS)를 **시중 워드프로세서의 UI를 갖춘 편집 환경**으로 개편한다. 기존 기능(7단계 파이프라인, 매크로 101종, 리모컨 UI, AI 검토, 슬라이드 생성)은 모두 유지하면서:

1. 워드프로세서 스타일 UI 셸 (메뉴바 + 리본 툴바 + 상태바)
2. 분할 화면: 마크다운 에디터(좌) | A4 페이지형 실시간 미리보기(우)
3. 내보내기 6종: `.hwpx` `.hwp`(신규) `.docx` `.pdf` `.md`(신규) `.pptx`
4. PPT 통합: 문서/슬라이드 탭으로 같은 워크스페이스 안에서 문서 → 슬라이드 → PPTX

### 사용자 결정 사항 (2026-07-05)

| 결정 | 선택 |
|---|---|
| 작업 위치 | 기존 코드를 `C:\project\docua`로 복사 후 개선 |
| HWP 범위 | HWPX + **바이너리 .hwp 생성도 시도** (제한 범위 명시) |
| 에디터 방향 | **분할 화면** (마크다운 소스 \| 서식 미리보기) — WYSIWYG 전환 아님 |
| PPT 연결 | **에디터에 통합** (탭 방식, 변환 버튼) |

## 2. 아키텍처 개요

기존 아키텍처를 유지한다. 변경은 프론트엔드 셸/에디터/미리보기와 백엔드 렌더러 1종 추가에 국한된다.

```
[프론트: Next.js 14]
  메뉴바 + 리본 툴바 (신규)
  ├─ 문서 탭: CodeMirror 6 에디터(신규) | A4 페이지 미리보기(개선)
  ├─ 슬라이드 탭: 기존 Fabric.js SlideEditor (이동·통합)
  └─ 리모컨 패널 (기존 유지, 우측 접이식)
        │ REST
[백엔드: FastAPI]
  7단계 파이프라인 (기존 그대로)
  renderers/: hwpx·docx·pdf (기존) + hwp_renderer.py (신규)
  .md 다운로드는 프론트 단독 처리 (백엔드 불필요)
```

## 3. 컴포넌트 설계

### 3.1 UI 셸 (신규: `components/shell/`)

- **MenuBar.tsx** — 파일(새 문서·열기·내보내기)·편집(실행취소·찾기)·서식(제목·굵게 등)·삽입(표·이미지·차트·수식·도표)·도구(매크로·AI 검토·설정). 각 항목은 에디터 명령 또는 기존 API 호출로 연결.
- **RibbonToolbar.tsx** — 서식 그룹(글꼴 표시·굵게/기울임/밑줄·정렬·목록), 삽입 그룹(표 그리드 선택기·이미지·수식·차트), AI 그룹(AI 검토 = 기존 R1 매크로, 슬라이드로 변환). 버튼은 **마크다운 문법 삽입/래핑** 방식으로 동작 (예: 굵게 = 선택 영역을 `**…**`로 감싸기).
- **StatusBar.tsx** — 글자 수·쪽 수·감지된 양식 종류·내보내기 포맷 뱃지.
- **DocumentTabs.tsx** — 문서 | 슬라이드 탭 전환. Zustand 스토어에 `activeTab` 추가.

기존 `TopBar.tsx`(로그인·사용량 뱃지)는 메뉴바에 흡수한다.

### 3.2 에디터 (교체: `components/editor/`)

- CodeMirror 6 (`@codemirror/lang-markdown`, `@codemirror/view` 등) 도입.
- 기능: 마크다운 구문 강조, Ctrl+B/I/U 단축키 → 문법 래핑, Tab 들여쓰기(기존 CodeTextarea 동작 이식), 다단계 undo, 현재 줄 강조.
- 기존 `InsertVisualBar`(도표·수식·차트 삽입)와 `FormFillPanel`, `HwpDropZone`은 CodeMirror의 dispatch API로 재연결.
- 디바운스 자동 변환: 2.5초 → **1초**로 단축 (기존 `docuax:auto-convert` CustomEvent 유지).
- 리본 툴바 ↔ 에디터 연결: 에디터 인스턴스를 Zustand 스토어에 노출하거나 command registry 패턴 사용.

### 3.3 미리보기 (개선: `components/preview/`)

- 기존 블록 미리보기를 **A4 페이지 시뮬레이션**으로 확장: 210×297mm 비율 페이지 카드, 여백, 쪽 나눔 계산(높이 측정 기반 근사), 쪽 번호 표시.
- 검토 태그(빨강·파랑·노랑) 표시는 기존 그대로 유지.
- 쪽 나눔은 근사치임을 인지 — 실제 쪽 수는 렌더러(hwpx/docx/pdf) 결과와 다를 수 있으며, 이는 허용 범위로 한다 (상태바에 "약 N쪽" 표기).

### 3.4 내보내기 (확장)

내보내기 드롭다운 (메뉴바 우측):

| 포맷 | 경로 | 상태 |
|---|---|---|
| .hwpx | `GET /render/{id}/hwpx` | 기존 |
| .hwp | `GET /render/{id}/hwp` | **신규** (아래 3.5) |
| .docx | `GET /render/{id}/docx` | 기존 |
| .pdf | `GET /render/{id}/pdf` | 기존 |
| .md | 프론트에서 현재 에디터 소스를 Blob 다운로드 | **신규** (백엔드 불필요) |
| .pptx | 슬라이드 탭 경유 (문서 → 슬라이드 변환 → pptxgenjs) | 기존 이동 |

### 3.5 HWP 바이너리 렌더러 (신규: `renderers/hwp_renderer.py`)

구형 HWP 5.0(OLE 복합문서) 라이터를 `olefile` 기반으로 직접 구현한다.

- **1차 지원 범위 (보장)**: 문단, 제목 수준, 굵게/기울임/밑줄, 글자 크기, 기본 표(셀 병합 없는), 목록.
- **1차 제외**: 이미지, 차트, 수식, 도표, 셀 병합 표, 표지 서식 → 이 요소가 포함된 문서는 해당 요소를 텍스트 대체(placeholder)로 강등하고 응답 헤더에 경고 목록 포함.
- **구조**: FileHeader 스트림 + DocInfo 스트림(문서 속성·글꼴·문자모양·문단모양 레코드) + BodyText/Section0 스트림(문단 레코드). zlib 압축 적용. HWP 5.0 공개 스펙(한컴 공개 문서) + 기존 `docs/legal/hwp-compatibility.md`의 정오표 27건 참조.
- **검증**: 생성 파일을 kordoc(프론트 의존성, HWP 파서)으로 재파싱하는 왕복 테스트를 pytest에 포함. 한글 2020/2024 실기 열림 확인은 수동 체크리스트.
- **실패 처리**: 렌더링 실패 시 HTTP 응답으로 명확한 오류 + UI에서 "HWPX 형식 사용 권장" 안내와 HWPX 대체 다운로드 버튼 제공.

### 3.6 PPT 통합

- `components/slides/`의 SlideEditor·SlideGeneratorPanel·SlideExportButton을 별도 페이지에서 **슬라이드 탭 내부로 이동**.
- 리본의 "슬라이드로 변환" → 기존 `POST /slides/generate`(문서 기반 AI 슬라이드 생성) 호출 → 슬라이드 탭으로 자동 전환 → Fabric.js로 편집 → PPTX 다운로드.
- 슬라이드 엔진(Fabric.js·pptxgenjs·테마 추출)은 재작성하지 않는다.

## 4. 데이터 흐름

1. 사용자가 CodeMirror에 마크다운 입력 → 1초 디바운스 → `POST /convert` → preview JSON → A4 페이지 미리보기 갱신.
2. 리본/메뉴 버튼 → 에디터에 마크다운 문법 삽입 → 1과 동일 흐름.
3. 매크로 실행(리모컨) → `POST /execute-macro` → 갱신된 preview 반영 (기존 흐름 그대로).
4. 내보내기 → 포맷별 render 엔드포인트 (md만 프론트 단독).
5. 슬라이드로 변환 → `POST /slides/generate` → 슬라이드 탭.

## 5. 오류 처리

- HWP 내보내기: 3.5의 강등·경고·대체 다운로드 정책.
- 변환 API 실패: 미리보기 영역에 마지막 성공 상태 유지 + 비침투적 오류 배너 (기존 패턴 유지).
- CodeMirror 도입 후 대용량 문서(1만 줄+) 성능: CodeMirror 6는 가상 스크롤 내장으로 기존 textarea보다 우수 — 별도 대응 불요.

## 6. 테스트 전략

- **백엔드**: `test_hwp_renderer.py` 신규 (레코드 구조 단위 테스트 + kordoc 왕복 파싱 검증 + 미지원 요소 강등 테스트). 기존 pytest 스위트(파이프라인·매크로·통합) 회귀 확인.
- **프론트**: 리본 툴바 명령(굵게·표 삽입 등) → 에디터 텍스트 변화 Jest 테스트. 탭 전환·내보내기 드롭다운 렌더링 테스트.
- **E2E**: Playwright 1시나리오 — 마크다운 입력 → 미리보기 확인 → 6종 내보내기 각 1회 다운로드 성공.

## 8. 구현 순서 (개요)

1. UI 셸 (메뉴바·리본·상태바·탭) — 기존 기능 연결
2. CodeMirror 6 에디터 교체
3. A4 페이지 미리보기
4. .md 다운로드 + 내보내기 드롭다운 통합
5. 슬라이드 탭 통합
6. HWP 바이너리 렌더러 (가장 위험도 높음 — 마지막, 독립적)
7. E2E 검증

상세 구현 계획은 writing-plans 단계에서 별도 작성한다.
