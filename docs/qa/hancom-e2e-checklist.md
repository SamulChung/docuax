# 한컴 한글 E2E QA 체크리스트

DocuAX가 생성한 HWPX를 한컴 한글에서 실제 열어 검증하는 절차. 출시 전 필수.

## 준비

- [ ] 한컴 한글 2024 또는 2022 라이선스 PC
- [ ] DocuAX 백엔드 실행 (`uvicorn app.main:app --port 8000`)
- [ ] 프론트엔드 실행 (`npm run dev`)
- [ ] 6개 빌트인 샘플 + 1개 사용자 업로드 양식 준비

## 시나리오 1 — 빌트인 샘플 6종 시각 검증

각 샘플을 변환 → HWPX 다운로드 → 한컴에서 열기:

| 샘플 | 확인 항목 |
|---|---|
| 주간 업무 보고 | 제목 22pt 네이비, H2 16pt, 표 5×4, 표 헤더 회색 |
| 협조 요청 공문 | 4단계 글머리 □○―※, 결재선 라인, 표 4×4 |
| 안내·통보 공문 | 일정표 7행, ※ 유의사항 |
| 사업 제안서 | 5장 구조, 가/나/다 번호 매기기, 예산 표 |
| 회의록 | 참석자 표, 결의사항 ※, 다음 회의 |
| 내부 메모 | 짧은 구조, H3 들여쓰기 |

**합격 기준** (각 샘플):
- [ ] 한컴에서 열기 오류 없음
- [ ] 제목·헤딩이 본문과 시각적으로 구분
- [ ] 표가 페이지 폭 내 정상 표시
- [ ] 한국어 폰트(맑은 고딕) 깨짐 없음
- [ ] 글머리 마커(□ ○ ― ※) 보존
- [ ] 페이지 여백 정상 (A4 25mm 권장)

## 시나리오 2 — 매크로 직접 호출 후 다운로드

리모컨에서 다음 매크로를 차례로 실행 후 HWPX 다운로드, 한컴에서 확인:

| 매크로 | 확인 |
|---|---|
| T1 표 생성 (5행 4열) | 한컴에서 정확히 5×4 표 |
| T4 헤더형 표 | 첫 행 회색 배경 |
| T18 합계 자동 | 마지막 행에 "합계" + 숫자 |
| B6 번호 매기기 | 1./2./3. 정확 표시 |
| B7 가/나/다 | 한국식 번호 정확 |
| G14 한자 변환 | "회사(會社)" 식 표시 |
| R7 맞춤법 검사 | 빨강 태그 → HWPX 텍스트 색 변화 |

## 시나리오 3 — 한컴 → DocuAX 라운드트립

1. 한컴에서 양식 문서 작성 → `.hwpx` 저장
2. DocuAX 양식 라이브러리에 업로드
3. 추출된 마크다운 확인 (텍스트 보존)
4. 변환 → HWPX 다운로드 → 한컴에서 비교

**합격 기준**:
- [ ] 한국어 본문 100% 보존
- [ ] 표는 행·열 수 일치
- [ ] 일부 서식 손실은 허용 (양식 → 마크다운 변환 한계)

## 시나리오 4 — 결재선·머리말·바닥글

현재 미지원 — 추후 v2:
- [ ] 결재선 자동 삽입
- [ ] 머리말에 문서번호·시행일자
- [ ] 바닥글에 페이지 번호

## 시나리오 5 — 인쇄·PDF 출력

한컴에서:
- [ ] 미리보기 화면 정상 (페이지 분할 자연스러움)
- [ ] PDF로 내보내기 → 원본과 비교
- [ ] A4 한 페이지에 적절한 분량
- [ ] 한국어 폰트 임베디드 (다른 PC에서 열어도 깨짐 X)

## 자동화 가능 항목

DocuAX는 OWPML 구조 검증을 자동화함 (`tests/test_macros_smoke.py`). 한컴 시각 검증은 사람 눈으로 해야 하나, 다음은 향후 자동화 가능:

- HWPX → PDF 변환 (LibreOffice headless) → PDF 시각 diff (PixelMatch)
- 한컴 한글 OLE 자동화 (Windows COM, 한컴 SDK 필요)
